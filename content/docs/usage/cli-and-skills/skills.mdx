AstroBox CLI Skills（`abcli`）是专为 AI Agent 设计的结构化能力封装。它将 AstroBox CLI 的命令、输出解析和错误处理规范化为 Agent 可直接遵循的协议，确保 AI 在操作 AstroBox 时准确、安全、可恢复。

## 什么是 CLI Skills

CLI Skills 位于 [AstroBoxSkills](https://github.com/AstralSightStudios/AstroBoxSkills/tree/master/abcli) 仓库中，核心文件包括：

| 文件 | 说明 |
|------|------|
| `SKILL.md` | 主技能定义与决策树，Agent 应优先遵循 |
| `references/commands.md` | 完整命令参考，包含所有参数和输出格式 |
| `references/errors.md` | 错误目录与恢复策略 |
| `references/output-parsing.md` | 输出解析模式（正则表达式与字段提取）|
| `scripts/run_abcli.py` | 辅助脚本，自动处理 npx 并发冲突 |

## 何时触发 CLI Skills

Agent 在以下场景中应当使用 `abcli`：

- 用户要求连接/配对设备
- 用户要求搜索、下载或安装表盘/应用
- 用户询问 AstroBox 状态或设备信息
- 用户提到 authkey、provider、设备 MAC 地址等关键词
- 用户需要刷新提供方缓存或排查安装问题

**不应触发**的场景：

- 手环应用开发（应使用插件开发文档）
- 自定义固件或硬件规格讨论
- 与 AstroBox 无关的一般 npm 错误

## 快速启动方式

Agent 可以通过以下方式调用 CLI：

```bash
# 推荐：通过 npx 运行（无需安装）
npx astrobox-cli <command> [options]

# 本地开发环境
pnpm cli <command> [options]
```

为避免 npx 并发冲突，Skills 仓库提供了 Python 辅助脚本：

```bash
python scripts/run_abcli.py <command> [options]
```

该脚本会在遇到 `ENOTEMPTY` 错误时自动清理缓存并重试。

## 核心决策树

Agent 收到用户请求后，应按以下路由选择命令：

### 查看状态/设备

```
用户："我的设备连接了吗？"
→ npx astrobox-cli status
→ npx astrobox-cli device list
```

### 连接新设备

```
用户："帮我连接手环"
→ npx astrobox-cli device list              # 查看已有设备
→ npx astrobox-cli device connect --name "..." --addr "..." --authkey "..."
→ 提示用户在物理设备上点击确认
→ npx astrobox-cli device show <addr>       # 验证连接
```

### 搜索并安装资源

```
用户："帮我找个初音表盘"
→ npx astrobox-cli provider refresh OfficialV2
→ npx astrobox-cli provider page OfficialV2 --keyword "miku" --limit 20
→ npx astrobox-cli provider item OfficialV2 <id>
→ npx astrobox-cli provider download OfficialV2 --id <id> --device <key>
→ curl -L -o "resource.bin" "<url>"
→ npx astrobox-cli install "./resource.bin" --wait
```

### 仅获取下载链接

```
用户："给我这个表盘的下载链接"
→ npx astrobox-cli provider refresh OfficialV2
→ npx astrobox-cli provider page OfficialV2 --keyword "..."
→ npx astrobox-cli provider item OfficialV2 <id>
→ npx astrobox-cli provider download OfficialV2 --id <id> --device <key>
→ 将 url 字段返回给用户
```

### 故障排查

```
用户："安装失败了"
→ npx astrobox-cli status                   # 检查 AstroBox 是否运行
→ npx astrobox-cli queue status             # 查看具体错误
→ 根据错误目录给出恢复建议
```

## 关键规范

### 搜索前必须刷新缓存

提供方缓存可能过期。Agent 在执行关键词搜索前，**必须先调用** `provider refresh <name>`，否则可能返回过时或空的结果。

### 使用 `--keyword` 而非 grep

`provider page` 的 `--keyword` 参数在服务端执行过滤，能命中所有分页的结果。将输出通过 `grep` 过滤只能看到当前页的数据，会遗漏其他页面的匹配项。

### 从 `provider item` 提取 device key

`provider download` 所需的 `--device` 参数值必须从 `provider item` 输出的 `Downloads:` 部分提取。格式如下：

```
Downloads:
  Xiaomi Smart Band 9 Pro (xmb9p)
```

括号中的 `xmb9p` 即为 device key。**禁止猜测**，必须从详情中获取。

### 安装是异步的

默认情况下 `install` 命令会立即返回 `{"ok": true, "message": "queued"}`，实际传输在后台进行。

如需实时跟踪进度，使用 `--wait`：

```bash
npx astrobox-cli install ./app.rpk --wait
```

Agent 在帮用户安装资源时，应主动使用 `--wait` 并汇报进度。

### 避免并发执行 npx

多个 `npx astrobox-cli` 进程同时运行可能触发 npm 缓存冲突（`ENOTEMPTY`）。Agent 应当：

- 依次执行命令，而非并行发起
- 使用 `scripts/run_abcli.py` 辅助脚本自动处理冲突
- 遇到 `ENOTEMPTY` 时执行 `rm -rf ~/.npm/_npx/*` 后重试

## 输出解析参考

Agent 需要解析 CLI 的纯文本输出。以下是核心模式：

| 输出 | 解析模式 |
|------|----------|
| 设备行 | `- (.+) \(([^)]+)\) \[(connected|disconnected)\]` |
| 资源条目 | `\[(\w+)\] (.+)` + `  id: (.+)` |
| 下载信息 | `  version: (.+)`, `  file:\s+(.+)`, `  url:\s+(.+)` |
| 队列表格 | 按 `\|` 分割并 trim 各字段 |
| 错误 | `Error: <message>` 在 stderr 中，退出码为 1 |

完整的解析模式请参考 [AstroBoxSkills/references/output-parsing.md](https://github.com/AstralSightStudios/AstroBoxSkills/blob/master/abcli/references/output-parsing.md)。

## 错误处理

| 错误 | 原因 | 恢复操作 |
|------|------|----------|
| `Could not reach AstroBox...` | 桌面端未运行 | 提示用户启动 AstroBox |
| `File does not exist:` | 路径错误 | 验证路径 |
| `Device not found:` | MAC 地址错误 | 运行 `device list` 确认 |
| `ENOTEMPTY` | npx 并发冲突 | 清理 `~/.npm/_npx/*` 后重试 |
| `没有已连接的设备` | 设备未连接 | 重新连接设备 |

完整错误目录请参考 [AstroBoxSkills/references/errors.md](https://github.com/AstralSightStudios/AstroBoxSkills/blob/master/abcli/references/errors.md)。
